## Context

Akul forked `koala73/worldmonitor` to `AkulxSharma/worldmonitor` (now synced, local clone lives at `sessions/worldmonitor/worldmonitor/`, notes at `sessions/worldmonitor/summary.md`). He wants to turn it into his own product: (1) his own UI/brand instead of "World Monitor," and (2) data that WorldMonitor currently locks behind its Pro paywall, sourced from free/alternate places instead, so he can use it for his own geopolitical-situational-awareness tool without paying WorldMonitor's own subscription back to itself.

Two research passes (Explore agents) mapped the actual code:
- **UI/branding**: theming is CSS custom properties (`src/styles/main.css`, two `:root` blocks), no JS theme object. The `happy` variant already proves the reskin pattern — a full `[data-variant="happy"]` CSS override file (`src/styles/happy-theme.css`) plus a font swap. `Panel.ts` (base class every panel extends) drives all chrome via CSS classes, not inline hex — favorable for a reskin. Branding text ("World Monitor") is **not** centralized: hardcoded across ~44 files including all 28 locale JSONs, plus `index.html`'s meta/JSON-LD block and a 4th place — an inline pre-paint loading skeleton with its own hardcoded hex colors (`index.html:221-407`).
- **Paywall**: gating is real, three different flavors, not one flag:
  - **(a) UI-only** — ProBanner, PRO badges, widget quotas, billing-portal buttons. No data behind these; deleting them changes zero functionality other than the upsell nag.
  - **(b) LLM-generated analysis** — stock analysis, country intel briefs, situation deduction, market implications, regional snapshots, event classification, WM Analyst chat. These hit WorldMonitor's own paid backend (`premiumFetch()` → `server/gateway.ts`, cross-checked server-side via `PREMIUM_RPC_PATHS` + `ENDPOINT_ENTITLEMENTS`). **Existing precedent already in the codebase**: `DailyMarketBriefPanel`/`InsightsPanel` already have a client-side fallback that generates the same kind of output using the *user's own* AI provider key (`isAnyAiProviderEnabled()`, `InsightsPanel.ts:337`) instead of WorldMonitor's backend. Free tiers exist for this today (Groq 14,400 req/day, OpenRouter 50 req/day) and are already wired into `.env.example`.
  - **(c) Licensed/derived datasets** — resilience score, national debt, supply-chain chokepoint/route analytics, sanctions pressure, UN Comtrade trade flows, tariffs, procurement tenders. These are genuinely different data, not just an LLM call — no shortcut, need real alternate free sources per domain.
  - Server-side enforcement is real too (Clerk role OR Convex entitlement, checked in `server/gateway.ts` + `server/_shared/entitlement-check.ts`/`premium-check.ts`), so a client-only gate removal does nothing for (b)/(c) — the backend still 402s.
  - **Discovered during implementation**: this same "relies on WorldMonitor's own live backend" pattern also hits non-paywalled features, e.g. `military:bases:active` and `loadPizzInt()` (Pentagon Pizza Index) — both show a bundled static snapshot on first paint, then hide themselves once the live fetch against WorldMonitor's Redis seed cache returns empty/errors. Not a Pro gate, just infra Akul doesn't operate — same fix path as (b)/(c).

## Track A — Rebrand to a custom UI

**Approach**: centralize branding, then reskin using the same mechanism the `happy` variant already proves works. Don't invent a new theming system.

1. **Create `src/config/brand.ts`** — single source of truth: `BRAND_NAME`, `BRAND_SHORT_NAME`, `SUPPORT_EMAIL`, `DOMAIN`, social handles, etc. Every hardcoded reference below should import from here instead of a literal string, so a future rename is a one-file edit.
2. **New theme file** `src/styles/<brand>-theme.css`, structured like `src/styles/happy-theme.css` (full `:root`-token override — bg/surface/border/text/overlay/map/font vars — no new mechanism needed). Load it as the *default* stylesheet rather than an opt-in variant, since this fork has one identity now, not six.
   - **Design direction is an open decision** (see questions below): the current app is deliberately dark, monospace, "information density over aesthetics" — that's a real, coherent OSINT-terminal identity that fits a geopolitical intel tool well. A reskin can mean new colors/type within that same philosophy, or a genuinely different visual language. Load `/impeccable` (`reference/product.md` register — this is dashboard/tool UI, not marketing) and `/emil-design-eng` guidance to pick tokens and motion that read as intentional, not templated — avoid the AI-slop defaults impeccable explicitly bans (cream/sand backgrounds, gradient text, generic card grids, tiny tracked eyebrows).
3. **`index.html`**: title, meta/OG/Twitter tags, all three JSON-LD blocks (`WebApplication`/`Organization`/`WebSite`), favicon links, and the inline pre-paint skeleton's hardcoded hex colors (4 theme variants: dark/light/happy-light/happy-dark — decide whether to keep the `happy` variant at all or fold everything into one brand).
4. **`src/app/panel-layout.ts:961`**: replace the literal `MONITOR` / `World Monitor` header logo markup. Start with a styled text wordmark (fast, no asset pipeline); a real mark/icon can come later as a `/impeccable delight` pass.
5. **Locale strings**: script a find-and-replace of the literal "World Monitor" across all 28 `src/locales/*.json` files plus the ~15 non-locale hardcoded files the explorer found (`SearchModal.ts`, `GlobeMap.ts`, `settings-window.ts`, `live-channels-window.ts`, `embed-main.ts`, `embed/embed-url.ts`, `services/webmcp.ts`, `services/story-share.ts`, `services/settings-constants.ts`, `app/event-handlers.ts`). Mechanical, not a design decision — do this as one pass.
6. **New favicon set** under `/favico/` matching the existing per-variant folder convention.
7. Leave `src/config/variants/*` (the 6-variant panel/map-layer system) alone — that's product surface, not branding, and Akul hasn't asked to change what data domains are shown, only how it looks and what's unlocked.
8. Verify: `npm run dev`, visually check header/favicon/title, check contrast (impeccable's 4.5:1 body-text rule) in both light/dark if both are kept, check mobile breakpoint (logo swaps to `.logo-mobile` at `panel-layout.ts:961`).

## Track B — Remove the paywall, replace what's genuinely gated

**Reframe**: Akul isn't running a SaaS he needs to bill for — the cleanest fix is to de-monetize the fork rather than preserve-and-bypass WorldMonitor's Clerk/Convex/Dodo billing stack.

1. **(a) UI-only gates — delete outright.** Remove `ProBanner.ts` and its mount call, strip `PRO`/`premium` badges in `UnifiedSettings.ts`, remove the `.upgrade-pro-section`, delete widget tier quotas in `widget-store.ts` (`MAX_HTML_CHARS_PRO` becomes the only limit). Zero data impact, pure cleanup — do this first, it's low-risk and shrinks the surface before touching (b)/(c).
2. **(b) LLM-analysis gates — generalize the existing free-tier pattern.** For each Pro-gated LLM feature (`MarketImplicationsPanel`, `DeductionPanel`, stock analysis in `stock-analysis.ts`, country intel briefs, regional snapshots, WM Analyst chat), add the same client-side-generation fallback `InsightsPanel`/`DailyMarketBriefPanel` already use: call the user's own configured `GROQ_API_KEY`/`OPENROUTER_API_KEY` directly instead of `premiumFetch()` to `server/gateway.ts`. Remove the `config/panels.ts` `premium: 'locked'` flags on these panels once each has a working client-side path. `FrameworkSelector`'s "Analytical Framework" gate can just be unlocked client-side (`isPremium` check removed) since the server-side `isCallerPremium` check in `deduct-situation.ts`/`get-country-intel-brief.ts`/`summarize-article.ts` will still 402 it unless Track B's server changes (next item) also land.
3. **Server-side entitlement checks**: since Akul controls the fork's own deploy, the actual unblock for (b) is removing/no-oping the entitlement checks in `server/gateway.ts` (`PREMIUM_RPC_PATHS` gate + the "legacy Pro bearer gate" at `gateway.ts:1436-1497`) and `server/_shared/entitlement-check.ts`/`premium-check.ts` on **his own deployment** — not on the upstream. This only matters if he deploys the server/API layer at all (see the earlier open Vercel-deploy question); if he only runs the client against his own AI keys and skips WorldMonitor's server/Convex/Clerk/Dodo stack entirely, this step is moot for (b) since there's no backend of his to gate.
4. **(c) Licensed/derived datasets — real sourcing work, own sub-track.** No shortcut: resilience score, national debt, supply-chain/chokepoint/route analytics, sanctions pressure, UN Comtrade flows, tariffs, and procurement tenders each need a genuine free/public data source researched and wired in (candidates: World Bank API, IMF, UN Comtrade's public bulk endpoint, OFAC/UN sanctions lists, USTR). This is 6-8 separate small data-integration projects, not one task — **needs Akul to prioritize which 2-3 actually matter for his geopolitical-situational-awareness use case** before scoping further; treating all of them as day-one work is how this stalls.
5. Verify: run `npm run dev` with real `GROQ_API_KEY`/`OPENROUTER_API_KEY` in `.env.local`, confirm a previously-locked panel (e.g. `DeductionPanel`) renders real output instead of the lock CTA; confirm `ProBanner` no longer mounts; grep for remaining `premium: 'locked'` entries in `config/panels.ts` to track what's left.

## Sequencing

Track A and B don't block each other — A1 (`brand.ts`) and B1 (delete UI-only gates) are both fast, low-risk, do-first items. B4 (alt data sourcing) is the long pole and should start last, scoped down to a short list Akul actually cares about.

## Decisions (confirmed by Akul)

- **Visual direction**: keep the dark/monospace/OSINT-terminal identity. Track A is a re-theme/re-brand within that existing aesthetic, not a new visual language — informs `/impeccable` token choices in step 2 (restrained, dark, information-dense; not a pivot to light/warm/friendly).
- **Track B (c) priority**: Akul wants all four flagged domains — resilience score, sanctions pressure, supply-chain/chokepoints, and trade flows/tariffs/debt — not narrowed further. Since that's effectively the full (c) list minus procurement tenders/event-classification-adjacent items, treat B4 as: scope and sequence these four as independent sub-projects (each gets its own source research + integration), still last in the overall sequence since it's the long pole, but no further de-prioritization within the four.

## Open question raised during implementation

Deploy topology for Track B3/B4/PizzINT fix: does Akul stand up his own backend (Vercel + Redis/Upstash + seed crons, replacing WorldMonitor's own infra), or go client-only (browser calls free/public APIs directly, no backend of his own, features that genuinely require server-side aggregation just don't exist in this fork)? This gates B3, and turns out to also gate unrelated live-data panels like PizzINT that aren't part of the paywall but share the same "needs WorldMonitor's live backend" dependency.
